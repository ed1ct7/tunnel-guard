# Tunnel Guard

Настольная панель для управления системной блокировкой интернета и правилами раздельной маршрутизации. Интерфейс на Tauri и React. VPN-профиль импортируется в v2rayN и обслуживается Mihomo.

## Windows 11

1. Открой Tunnel Guard. Во вкладке **Подключение** укажи установленный `v2rayN.exe`, имя TUN-адаптера и порт локального смешанного прокси. Приложение рассчитано на конфигурацию v2rayN с Mihomo в режиме TUN и контроллером на loopback. Для поддерживаемой схемы v2rayN порт контроллера в режиме TUN равен порту прокси плюс 6.
2. Запусти профиль в режиме **Rule**. Во вкладке **Защита** включи блокировку. Windows запросит права для отдельного процесса, который меняет брандмауэр. В окне появится фактический результат.
3. Во вкладке **Маршрутизация** добавляй домены, имена процессов или пути к программам и выбирай маршрут. В режиме **Только выбранное через VPN** весь трафик вне списка идёт напрямую, даже если kill switch включён и Mihomo работает. Список сохраняется в `prepend-rules` файла `guiConfigs/Mixin.yaml`. Включи **Enable Mixin Content** в настройках Mihomo в v2rayN и перезапусти ядро после изменения списка.
4. Закрытие окна сворачивает панель в область уведомлений. Чтобы вернуть системные правила, нажми **Выключить защиту**. Выход из панели через меню трея сам по себе не выключает правила.

Системная блокировка применяется ко всей Windows. Пока TUN исчез, обычные приложения теряют интернет. Правила `DIRECT` обрабатываются Mihomo при работающем клиенте. Сделай резервную копию профиля v2rayN перед его редактированием, ключи в настройки Tunnel Guard не копируются. Прежняя локальная политика брандмауэра сохраняется в `%LOCALAPPDATA%\TunnelGuard\original-policy.xml`.

Проверка при включении сравнивает HTTPS через TUN и локальный прокси, затем проверяет блокировку прямого IPv4-маршрута на нейтральном адресе. Режимы отдельных виртуальных машин и IPv6 требуют собственных проверок.

## Управление из скрипта или ИИ-агента

Установщик кладёт `guardctl.exe` рядом с основным приложением. Команды работают без запуска панели. Данные выводятся в stdout как JSON. При ошибке выполнения поле `ok` равно `false`, а код завершения отличен от нуля.

```powershell
.\guardctl.exe status
.\guardctl.exe config
.\guardctl.exe settings get
.\guardctl.exe settings set --client-path 'C:\v2rayN\v2rayN.exe' --adapter Mihomo --proxy-port 10808
.\guardctl.exe rules list
.\guardctl.exe rules active
.\guardctl.exe rules targets
.\guardctl.exe rules add domain example.org
.\guardctl.exe rules add process-name program.exe
.\guardctl.exe rules add process-path 'C:\Apps\program.exe'
.\guardctl.exe rules remove domain example.org
.\guardctl.exe start-client
.\guardctl.exe doctor
.\guardctl.exe core state
.\guardctl.exe core reload
```

Для режима «Только выбранное через VPN» сначала добавь хотя бы одно правило с маршрутом из `rules targets`, затем выбери режим. Первая строка ниже использует условное имя маршрута.

```powershell
.\guardctl.exe rules add domain example.org --via Server-4
.\guardctl.exe rules mode vpn-only
.\guardctl.exe rules mode profile
```

`settings set` обновляет только переданные параметры. `rules replace --file rules.json --expected snapshot.json` заменяет список по JSON-массиву строк. В `snapshot.json` сохрани вывод `guardctl config` в UTF-8 перед редактированием. Если подключение или исходный список уже изменились, команда вернёт ошибку и сохранит более свежие данные.

Панель и CLI читают одни файлы. Уже открытое окно подхватывает изменения, а при конфликте с несохранённым черновиком предлагает перечитать данные. `rules list` показывает сохранённый список, `rules active` — правила в запущенном Mihomo. После изменения списка выполни `core reload` (или перезагрузи ядро в v2rayN) и проверь `rules active`.

`doctor` только читает состояние: путь к v2rayN, ядро Mihomo, Enable Mixin Content, порты прокси и контроллера, TUN-адаптер, режим Mihomo. Поле `ready` равно `true`, когда готово всё, кроме Mixin и запущенного v2rayN. `core state` сравнивает сохранённые правила с правилами запущенного Mihomo: `applied` — совпадают, `pending` — нужна перезагрузка, `unknown` — причина в `detail`. `core reload` передаёт запущенному Mihomo сгенерированный v2rayN конфиг, в котором заменены только правила; v2rayN не перезапускается, файлы v2rayN не меняются. Команда откажет, если конфиг v2rayN устарел относительно запущенного ядра.

Команды `protection enable`, `protection disable --confirm` и `protection clean-legacy` требуют консоли, запущенной с правами администратора. CLI возвращает ошибку при нехватке прав. HTTP-сервер для управления Tunnel Guard не нужен.

## Группы процессов

Во вкладке **Процессы** можно создать группу по имени или пути к `.exe`, семейству пакета Windows, фрагменту аргументов конкретного `.exe` или точному имени службы. **Посмотреть** показывает найденные процессы. **Завершить** закрывает их вместе с дочерними процессами. Для общей кнопки включи в новую группу уже сохранённые группы.

Группы хранятся в `%LOCALAPPDATA%\TunnelGuard\process-groups.json`. Предустановленных групп в установщике нет. Пример нейтральной конфигурации:

```json
{
  "groups": [
    {
      "id": "editor",
      "title": "Редактор",
      "selectors": [{ "kind": "name", "value": "example-editor.exe" }]
    },
    {
      "id": "tools",
      "title": "Рабочие инструменты",
      "includes": ["editor"]
    }
  ]
}
```

```powershell
.\guardctl.exe processes list
.\guardctl.exe processes set --file groups.json --expected previous.json
.\guardctl.exe processes preview tools
.\guardctl.exe processes stop tools --confirm
```

`previous.json` содержит предыдущий JSON-вывод `processes list`. `stop` возвращает оставшиеся процессы и службы, а при частичном завершении код выхода равен `2`. Завершение относится к процессам текущего пользователя и сеанса. Для отдельно запущенных помощников добавь отдельные условия. Остановка служб зависит от прав Windows. Браузерные вкладки в общем процессе нельзя выбрать по названию сайта. Для отдельного браузерного профиля можно выбрать имя процесса и уникальный фрагмент аргументов.

## Сборка

В корне проекта `npm ci` и `npm run tauri -- build`. Для Windows нужны Rust MSVC, инструменты сборки C++ и WebView2. Выполняемый файл без установщика можно собрать с флагом `--no-bundle`.

Системная блокировка в этой версии реализована для Windows. Linux потребует отдельной реализации сетевой политики и выдачи прав.

## Структура репозитория

- `src/` — интерфейс (React + Vite).
- `src-tauri/` — Tauri-приложение и CLI `guardctl` (Rust), скрипты брандмауэра Windows в `src-tauri/src/windows/`.
- `legacy/` — ранние версии (PowerShell-прототипы и .NET), не поддерживаются.
